# HISTORY

このドキュメントは、`dev/hri_spotdog_follow` プロジェクトの開発経緯を、
「どのような問題意識があり、何を修正したか」を中心に時系列でまとめたものです。

対象実装:
- `dev/hri_spotdog_follow/spotdog_follow_human_square_room.py`
- `dev/hri_spotdog_follow/README.md`


## 2026-04-13: 初期立ち上げ (v0)

### 問題意識
- 既存の `dev/hri_agv` は HRI 用のベースとして有用だが、今回必要なのは
  「人の後方 1m を SpotDog が追従し続ける」専用プロジェクト。
- 既存環境差を混ぜると挙動比較が難しくなるため、移動領域・壁構成は完全に同一にしたい。

### 修正内容
- 新規プロジェクトディレクトリ `dev/hri_spotdog_follow` を作成。
- `spotdog_follow_human_square_room.py` を新規作成し、`hri_agv` と同等の
  10m x 10m 壁生成ロジックを移植。
- Human / SpotDog のスポーン、UE 接続、ログ出力まで一連の流れを整備。

### 効果
- `hri_agv` との差分が「追従制御ロジック」に集中し、挙動比較が容易になった。


## 2026-04-13: Human 移動ロジック (v1)

### 問題意識
- 要求仕様として Human は「直進し続け、障害物に当たったら向きを変えて再直進」が必要。
- 単純ランダム移動では再現性が低く、追従評価の基準がぶれる。

### 修正内容
- `human_control_loop` を実装。
- `humanoid_step_forward` を連続実行して直進維持。
- 移動量が閾値未満 (`HUMAN_COLLISION_MOVE_EPS_CM`) の場合を衝突相当とみなし回頭。
- 壁際では接触面接線方向を優先する回頭方針を採用。

### 効果
- Human の行動が仕様に近い形で安定し、SpotDog の追従評価が可能になった。


## 2026-04-13: SpotDog 追従コア制御 (v2)

### 問題意識
- 単純に人へ向かうだけでは「人の後ろ 1m」を維持できず、横付きや前方割り込みが起こる。
- 方向制御と距離制御を同一信号で扱うと調整が難しい。

### 修正内容
- 方向制御:
  - カメラ検出結果から画面中心誤差を角度誤差へ変換。
  - 誤差に比例した回頭 (`ROBOT_HEADING_KP`) を実装。
- 距離制御:
  - depth マップから推定した距離で追従速度を制御。
  - 目標距離 `FOLLOW_DISTANCE_CM=100` を中心にデッドバンド制御。
- 後方追従性の強化:
  - Human の向きから「後方 1m ターゲット」を生成。
  - 幾何学的後方条件が崩れた場合は rear ターゲットへの誘導をブレンド。

### 効果
- SpotDog が「人の中心を捉える」だけでなく「後方 1m を維持する」動きに近づいた。


## 2026-04-13: センサ統合とログ整備 (v3)

### 問題意識
- UE 内の見た目だけでは、制御が正しいか定量評価できない。
- 検出失敗時に制御が途切れると不安定になりやすい。

### 修正内容
- SpotDog に同期する仮想カメラ姿勢更新を実装。
- RGB + depth のセンサ処理を統合:
  - RGB: 人物検出
  - depth: ROI 距離推定
- センサ失敗時の幾何フォールバックを導入。
- `sim_data` に追従誤差・検出状態・距離推定値・バックエンド情報を記録。
- CSV 出力 (`spotdog_follow_log.csv`) とメトリクス集計を追加。

### 効果
- 追従品質をログで追跡可能になり、チューニングサイクルが回しやすくなった。


## 2026-04-13: 見失い時サーチ + モニタ初版 (v4)

### 問題意識
- 人を見失ったとき、従来は幾何フォールバックに依存し、再検出までの回復が遅い。
- 実行中に「カメラ映像」と「距離時系列」を同時に観察したい。

### 修正内容
- 見失い時サーチを実装 (初版):
  - 一定時間未検出でその場回転。
- リアルタイムモニタを追加:
  - カメラ表示ウィンドウ (TRACKING / SEARCHING オーバーレイ)
  - 距離時系列ウィンドウ

### 効果
- 追従中の状態確認とデバッグが容易になった。

### 後続課題
- サーチ回転が離散的で、体感として不連続。
- ウィンドウのライフサイクルを運用フローにさらに合わせたい。


## 2026-04-13: モニタ運用性改善 + サーチ連続回転化 (v5)

### 問題意識
- 要件として「Run Simulation 直前にウィンドウ起動」「終了後も自動で消えない」が必要。
- 現状はシミュレーション終了に追従してウィンドウが閉じる経路があり、観測が中断される。
- サーチ回転が不連続で、探索行動として自然でない。

### 修正内容
- モニタの停止制御をシミュレーション停止と分離:
  - `monitor_stop_event` と `simulation_done_event` を追加。
- Run Simulation 直前にプレースホルダ付きでウィンドウを先行起動。
- シミュレーション終了後もウィンドウを維持し、`q` / `ESC` で手動クローズ可能に変更。
- サーチ回転を連続化:
  - 回転周期を 2 秒 / 回転 (`SEARCH_SPIN_PERIOD_S=2.0`)。
  - 短スライス回転 (`SEARCH_ROTATE_SLICE_S=0.05`) を繰り返す連続挙動へ変更。

### 効果
- 実験者がシミュレーション終了後も結果画面を確認し続けられる。
- Searching モードの回転が滑らかになり、再検出までの探索挙動が自然化。


## 2026-04-13: 波形可視化の軸・グリッド追加 (v6)

### 問題意識
- 以前の波形は見た目は分かるが、時間軸・距離軸の読み取りが困難。

### 修正内容
- 距離波形ウィンドウに以下を追加:
  - 縦軸ラベル: Distance [cm]

  - 縦横グリッド線

### 効果
- 「いつ」「どれだけ」距離誤差が出たかを定量的に読み取れるようになった。


## 2026-04-13: 遠距離人物検知の強化 (v7)

### 問題意識
- 遠距離では人物の見かけサイズが小さく、単一スケール検知で見落としが増加。
- 低コントラスト状況で輪郭が弱く、HOG の応答が低下しやすい。

### 検討した一般的アルゴリズム
- コントラスト正規化 (CLAHE)
- マルチスケール検知 (画像ピラミッド / アップサンプル)
- タイル分割推論 (SAHI 系アプローチ)
- 時間方向の安定化 (短時間トラッキング / hold)

### 修正内容
- 前処理:
  - CLAHE + シャープ化を導入 (`VISION_ENABLE_CLAHE`)。
- 空間方向の強化:
  - 通常スケール + アップサンプルスケール検知 (`VISION_FAR_UPSAMPLE`)。
  - タイル分割探索 (`VISION_ENABLE_TILED_SEARCH`, `VISION_TILE_OVERLAP`)。
- 候補統合:
  - 中心性、縦横比、遠距離ボーナス、時間的 IoU を加味したスコア選抜。
- 時間方向の強化:
  - 直近検出の短時間 hold (`+temporal_hold`)。
- YOLO 使用時も同じくタイル探索に対応。

### 効果
- 遠距離での見落としを減らし、検出断続による制御のガタつきを抑制。

## 現在の運用ポイント

- モニタはシミュレーション終了後も残るため、終了時に
  `q` / `ESC` で明示的に閉じる運用。
- 遠距離検知の計算コストが増えたため、FPS 優先時は以下を下げると軽量化可能:
  - `VISION_ENABLE_TILED_SEARCH = False`
  - `VISION_FAR_UPSAMPLE` を小さくする
